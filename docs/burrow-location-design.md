# 땅굴 위치: 캠퍼스·층으로 나누기 (아이디어)

- 날짜: 2026-11-13
- 요청: 사람을 지역(캠퍼스)과 층으로 나눈다(예: 서울 1층, 서울 2층, 대전 1층). 땅굴 위치도 그 기준으로 나누려 한다. (1) 화면에 어떻게 보여줄지 (2) 자료구조·DB에 어떻게 저장할지 아이디어
- 지금 상태: 위치를 저장하지 않음. `fieldScene.ts`가 이웃 목록 순서로 Figma 둔덕 두 곳 + 미리 정한 먼 자리 5곳에 놓음, 최대 8굴 (땅 구멍 셰이더 한도)
- 전제: 가입(F2 회원가입 3)에서 이미 캠퍼스 · 기수 · 층을 받고, 프로필에 공개함(F0 4). 반은 받지 않음

## 1. 화면

### 추천: 두 단계 — "층 들판"(3D) + "캠퍼스 단면도"(2D)
1. **층 들판 (기본)**: 한 층 = 들판 하나. 탐색에 들어가면 내 층 들판에서 시작한다. 지금 탐색 화면을 그대로 쓰고, 굴 수만 늘린다
2. **캠퍼스 단면도 (층 바꾸기)**: 땅을 옆에서 자른 그림. 캠퍼스마다 언덕 하나, 층마다 지층 한 줄. 줄마다 "서울 2층 · 땅굴 86개 · 나와 같은 관심사 12명"을 보여주고, 누르면 그 층 들판으로 간다
   - 세계관: 건물의 층을 땅의 지층으로 바꾼다. 두더지가 층을 옮길 때는 굴로 들어가 아래·위로 파고 내려가 다른 층 굴에서 나온다 (`mole_burrow_enter` → 카메라 이동 → `mole_burrow_exit`, 이미 정한 이동 모션을 그대로 씀)
   - 2D라 그래픽 가속이 꺼진 PC에서도 가볍다

### 층 들판 안에서 자리 배치
| 방식 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **관심사 동네 (추천)** | 들판을 대표 분류 11개로 부채꼴처럼 나누고, 내 가장 큰 취향 분류의 동네 안쪽부터 빈자리에 앉힌다 | 걸어다니기만 해도 비슷한 사람이 모여 있음 (서비스 목적과 맞음). 동네 팻말로 길 찾기 쉬움 | 관심사를 바꿔도 집은 그대로 둘지 정해야 함 |
| 들어온 순서 나선 | 가운데부터 바깥으로 나선 순서로 채움 | 가장 단순, 자리가 안 바뀜 | 배치에 의미가 없음 |
| 실제 자리 흉내 | 교실·반 배치를 본뜸 | 현실과 연결 | 반을 받지 않기로 함, 사생활 우려 |

- **많아질 때**: 한 층에 100명 안팎을 가정. 가까운 굴(약 8개)만 구멍 뚫린 3D 굴로, 나머지는 작은 둔덕·팻말로 줄여 그린다. 카메라 거리에 따라 바꿔 끼움 (구멍 셰이더 8개 한도와 저사양 모드 때문)
- **내 굴 찾기**: 들어오면 내 굴에서 나옴. 미니맵 또는 "내 굴로" 버튼
- **다른 층 사람 찾기**: 추천 친구·단골·프로필 팝업의 "땅굴 놀러가기"는 층과 상관없이 바로 그 굴로 간다 (층 들판으로 이동 후 그 굴에서 나옴)

## 2. 저장

### 추천: "자리(plot)" 테이블 + 육각 격자 좌표
좌표를 실수(x, z)로 저장하지 않고 **층마다 정해진 격자 칸**에 사람을 앉힌다. 겹침이 생기지 않고, 빈자리 찾기·주변 불러오기가 쉽다. 실제 화면 좌표는 칸 번호로 계산한다 (칸 하나 약 6m, 육각 격자라 자연스럽게 보임).

```sql
campus (id, name)                         -- 서울, 대전, 광주, 구미, 부울경
floor  (id, campus_id, level, label,      -- 서울 · 2 · "서울 2층"
        radius)                           -- 들판 크기(격자 반지름)

burrow_plot (
  id,
  floor_id   → floor.id,
  q, r       -- 육각 격자 좌표 (가운데 0,0)
  sector     -- 관심사 동네(대표 분류 id), 칸을 만들 때 정해짐
  user_id    → user.id  NULL이면 빈자리
  assigned_at,
  UNIQUE (floor_id, q, r),
  UNIQUE (user_id)                         -- 한 사람 한 자리
)
INDEX (floor_id, sector, user_id)          -- 동네별 빈자리 찾기
INDEX (floor_id, q, r)                     -- 주변 칸 불러오기
```

- 사용자 테이블에는 이미 `campus_id`, `floor`(층), `cohort`(기수)가 있음. 자리는 `burrow_plot`에서만 관리
- 땅굴 안(방·가구)은 지금처럼 사용자별 별도 저장. 자리를 옮겨도 방은 그대로

### 동작
| 언제 | 처리 |
|---|---|
| 가입 끝(온보딩 4 관심사 확정) | 내 층에서 내 대표 분류 동네의 가운데에 가장 가까운 빈 칸을 배정. 동네가 꽉 차면 이웃 동네, 그래도 없으면 층 반지름을 한 겹 늘림 |
| 관심사 변경 | 자리는 그대로 (자주 바뀌면 길 찾기가 어려움). "이사하기"를 따로 둘지 선택 |
| 층 변경 (내 정보 수정) | 옛 칸을 비우고 새 층에서 같은 규칙으로 배정. 단골 목록은 사람 기준이라 영향 없음 |
| 탈퇴 | 칸 비움 (바로 재사용할지, 며칠 비워 둘지 결정) |
| 들판 열기 | `floor_id`로 그 층 칸 전체(100개 안팎)를 한 번에 읽음. 사람 정보는 닉네임·관심사·두더지 모습만. 자주 안 바뀌므로 층 단위로 캐시 |

### 다른 방법과 비교
| 방법 | 장점 | 단점 |
|---|---|---|
| **격자 칸 테이블 (추천)** | 겹침 없음, 빈자리 찾기 쉬움, 자리 고정 | 칸 크기를 미리 정해야 함 |
| 사용자 테이블에 x, z 실수 저장 | 자유로운 배치 | 겹침 검사 필요, 빈자리 찾기 어려움 |
| 저장 안 하고 매번 계산 (해시·정렬) | 서버 저장 없음 | 사람이 늘거나 빠지면 다른 사람 집이 움직임 |

## 정해야 할 것
1. 다른 층·다른 캠퍼스 들판에도 걸어서 놀러 갈 수 있는지 (아니면 내 층만 걸어 다니고 다른 층은 바로 이동만)
2. 자리 배치 방식 (관심사 동네 / 들어온 순서)
3. 관심사를 바꾸면 이사하는지
4. 한 층 최대 인원 가정 (칸 수·들판 크기)
