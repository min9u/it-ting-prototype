## 먼저 정해야 할 것 5개
백엔드 API 명세(ERD는 [backend/erd-2026-11-16.md](backend/erd-2026-11-16.md)에 완료)를 쓰기 전에, 또는 여러 화면에 한꺼번에 영향을 주는 것부터.

1. **G-53 모임 분류(카테고리 vs 대표 관심사)**: ERD `meetup.category`는 11-16 명세(모임 전용 카테고리)를, 구현은 결정 M15(대표 관심사 + 태그 3개)를 따르고 있어 모임 API·필터·카드 색·커뮤니티 모임 연결이 모두 여기에 걸림
2. **G-04 차단 기능이 있는지**: 최신 명세(F8·F10·프로필 팝업)에서는 빠졌는데 F5 방노트·F7 문장·구현에는 남아 있음. ERD에 차단 테이블이 없어서, 있다면 목록 API마다 숨김 조건이 달라짐
3. **G-60 신고 대상과 처리(+ G-81)**: `report.target_type` 값(모임 포함 여부), 자동으로 가릴 대상, 처리 기록 칼럼을 정해야 F4·F7·F8·F11 신고 API가 나옴
4. **G-32 들판 입구 규칙(+ G-41 탈퇴 빈 번호, G-42 새 학기 열기)**: 학기 중 캠퍼스·층을 바꿀 때 자리 번호, 탈퇴한 자리, 학기를 여는 주체가 `term`·`burrow_entrance` API와 탐색 화면 배치를 정함
5. **G-06 시간 기준 자동 처리(+ G-01 시간 표기)**: 자동 미승인·지난 모임·요청 5일·방명록 7일·알림 30일·추천 "하루"의 기준 시간대와 처리 방식(예약 작업 / 조회할 때 계산)이 API가 돌려줄 상태값을 바꿈
