# 디굴디굴 서비스 명세

디굴디굴은 SSAFY 교육생만 들어오는 관심사 기반 만남 서비스다. 실명 대신 두더지 캐릭터와 "캠퍼스 · 기수 · 층"으로 자신을 드러내고(프로필 사진은 선택이다), 고른 관심사가 가구로 놓인 "땅굴"(내 방)이 프로필 역할을 한다. 사람을 검색해서 찾지 않고, 들판을 돌아다니다 만난다.

이 폴더가 서비스 명세의 **단 하나의 기준**이다. 무엇을 만들지 궁금하면 여기를 본다.

## 서비스 흐름

1. **가입**: 이메일 또는 Google로 시작해 Mattermost로 SSAFY 인증을 하고, 닉네임 · 두더지, 관심사, 질문 3개 답변을 정하면 땅굴이 만들어진다. → [02](02-auth.md), [03](03-onboarding.md)
2. **발견**: 내 캠퍼스-층의 들판을 두더지로 걸어다니며 남의 땅굴 입구를 만난다. 하루 한 번 추천 친구 3명을 받는다. → [05](05-explore-visit.md)
3. **방문**: 남의 땅굴에서 가구로 관심사를 구경하고, 방노트를 읽고, 방명록을 남기고, 단골로 담는다. → [05](05-explore-visit.md)
4. **대화**: 상대 땅굴에서 대화 요청을 보내고, 상대가 수락하면 1:1 대화방이 생긴다. → [05](05-explore-visit.md), [06](06-chat.md)
5. **모임**: 카테고리별 모임을 열고 신청하고 주최자가 승인한다. 확정되면 모임 대화방에 들어간다. → [07](07-meetup.md)
6. **커뮤니티**: 모임 홍보 · 모임 후기 · 자유 글과 댓글을 쓴다. → [08](08-community.md)

## 용어

| 낱말 | 뜻 |
|---|---|
| 두더지 | 사용자의 캐릭터. 프로필 사진을 올리지 않아도 두더지로 보인다 |
| 땅굴 | 사용자의 방이자 프로필. 관심사마다 정해진 가구가 하나씩 놓인다 |
| 들판(서버) | 땅굴 입구가 놓이는 탐색 공간. 학기 + 캠퍼스-층마다 하나다(예: 2026 하반기 서울-2층) |
| 소속 | 캠퍼스 · 기수 · 층. 반과 실명은 받지도 보여주지도 않는다 |
| 관심사 | 대분류 12개 아래 세부 관심사 90개가 있다([00 공통](00-common.md) 5). 사람 · 가구 · 겹치는 관심사는 세부 관심사, 커뮤니티 글 태그는 대분류를 쓴다 |
| 대표 관심사 | 내 관심사 목록의 맨 앞 것. 땅굴 무드(벽 · 바닥)를 정한다 |
| 방노트 | 땅굴 주인의 자기소개, 관심사, 질문 3개와 답변을 보여주는 패널 |
| 방명록(우체통) | 방문자가 땅굴에 남기는 짧은 글 |
| 단골 | 내가 담아 둔 남의 땅굴. 상대의 수락이 필요 없다(친구 기능은 없다) |
| 찻방 | 채팅 화면 가운데에 그려지는, 두더지들이 마주 앉는 방 |
| 카테고리 | 모임의 분류. 관심사와는 별개다 |
| 게시판 | 커뮤니티(F8)의 화면 이름. GNB 메뉴와 화면 제목은 “게시판”, 영역 이름 · 주소 · DB 이름은 “커뮤니티”다 |

## 이번 범위에 없는 것

만들지 않기로 정한 것이다. 다시 넣으려면 이 목록에서 지우고 해당 문서에 명세를 쓴다.

- 차단 기능, 친구 맺기
- 모임에 대한 신고, 모임의 "마감 임박" 표시 · 정렬 · 알림
- 휴대폰 · 태블릿 지원(데스크톱 웹만)
- 글 · 모임의 임시 저장, 땅굴 공유, 지난 모임에서 후기 쓰기로 가는 연결
- 언어 설정, 다크 모드, 메시지 삭제 · 읽음 표시, "접속 중" · "방문 중" 표시
- 비로그인 사용자의 커뮤니티 · 모임 · 실제 땅굴 열람(랜딩과 견본 방만 본다)

## 이 명세를 관리하는 법

- **명세는 이 폴더 하나다.** 파일 이름에 수정한 사람이나 날짜를 붙인 사본(`…(수정).md`, `…-v2.md`)을 만들지 않는다. 바뀐 이력은 git이 맡는다.
- **규칙은 한 곳에만 쓴다.** 여러 화면이 함께 쓰는 규칙은 [00 공통](00-common.md)에 한 번만 쓰고, 화면 문서에서는 "00 공통 N"으로 가리킨다. 어떤 기능은 처음 나오는 화면에서만 정의하고, 다른 화면은 "모임 – 상세 6과 같다"처럼 가리킨다.
- **설계도 수준까지만 쓴다.** 어떤 화면과 기능이 있는지, 무엇을 받고 보여주는지, 화면이 어떻게 이어지는지를 쓴다. 정확한 글자 수, 화면 배치, 구현 방법은 디자인과 구현 단계에서 정한다.
- **결정이 바뀌면 문서를 바로 고친다.** 무엇이 왜 바뀌었는지는 커밋 메시지에 쓴다. 아직 정하지 못한 것은 [아직 정하지 않은 것](open-issues.md)에 올리고, 정해지면 그 목록에서 지우고 본문에 반영한다.
- **Figma와의 관계**: 화면 그림은 Figma `it-ting 스켈레톤` 파일의 "02. 스켈레톤 기능 명세" 페이지에 있고, 문서의 화면마다 Figma 프레임 id를 적어 둔다. 글이 서로 다르면 이 문서를 기준으로 Figma를 고친다.
- 항목 번호는 Figma 명세 패널의 번호와 같다. 번호를 바꾸면 그 번호를 가리키는 다른 화면도 함께 고친다.
