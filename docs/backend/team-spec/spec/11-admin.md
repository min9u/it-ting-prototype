# 11. 운영 · 관리자

관리자가 자기소개 질문을 관리하고, 신고를 처리하고, 사용자를 조치하고, 공지를 올린다.

**관리자 화면의 세부는 추후 정한다.** 이 문서는 저충실도 기능 목록 한 장을 옮긴 것이다. 어떤 일을 화면으로 하는지만 적혀 있고, 화면 구성과 처리 흐름은 아직 없다.

- Figma: F11 운영 · 관리자 (`793:3929`)
- 공통 규칙: [00 공통](00-common.md)

## 관리자 – 기능 목록

- 들어오는 곳: 서비스 메뉴에 드러나지 않는 별도 주소(관리자 역할이 있는 계정만)
- 공통: [00 공통](00-common.md) 19 캠퍼스-층 · 학기

Figma 명세에 흐름 줄이 없다. 위의 두 줄은 항목 1에 적힌 내용을 옮긴 것이다. 2 ~ 4는 자기소개 질문 관리의 항목이다.

1. **메뉴**: 관리자는 일반 계정에 관리자 역할을 DB에서 직접 켠 사람이다. 관리자 화면은 서비스 메뉴에 드러나지 않는 별도 주소로 들어온다. 역할이 없는 계정에는 없는 주소처럼 보인다. 메뉴는 자기소개 질문 관리, 신고 처리, 사용자 조치, 공지 작성이다. 관심사 태그와 캠퍼스 · 층 목록([00 공통](00-common.md) 19) 관리, 탈퇴 사유 확인, 관리자 지정은 화면 없이 DB에서 직접 한다. 관리자 화면의 세부는 추후 정한다.
2. **질문 추가**: 질문 문구, 종류(관심사 / TMI), 관심사 질문이면 연결할 관심사 대분류를 입력해 추가한다. 준비하는 질문 전체는 관심사 질문 60%, TMI 질문 40%로 맞춘다.
3. **필터**: 전체 / TMI / 관심사.
4. **질문 목록**: 질문, 종류, 연결 대분류, 작업(수정)을 보여준다. 질문은 숨기거나 지우지 않는다.
5. **신고 처리 · 사용자 조치**: 상세 화면은 다음 단계에서 그린다.
   - 신고 처리: 글 · 댓글 · 사용자 · 방명록 글 신고 목록 확인과 처리 결과 기록, 가려진 글 · 댓글 · 방명록 글 복구, 방명록 글 삭제.
   - 사용자 조치: 계정 정지와 해제. 정지는 기간을 정해서 한다(예: 7일). 정지된 계정은 로그인할 때 사유와 기간을 팝업으로 본다([02 로그인 · 회원가입](02-auth.md#로그인)의 로그인 4).

## 영역 규칙

관리자가 하는 일이 다른 영역의 어느 항목과 이어지는지 모은다. 내용은 해당 항목이 기준이다.

- **신고**: 신고 대상 네 가지와 신고하는 곳은 [08 커뮤니티](08-community.md#커뮤니티--신고-팝업)의 신고 팝업 1에 있다. 글 · 댓글이 신고로 가려지는 조건과, 관리자가 복구하면 공개로 돌아오는 것은 신고 팝업 4에 있다. 방명록 글도 같은 조건으로 가려진다. 사용자는 신고가 쌓여도 자동 조치 없이 관리자가 확인한다(신고 팝업 4).
- **공지**: 관리자가 올린 공지는 [10 설정 · 계정](10-settings.md#설정--공지사항)의 공지사항과 공지사항 상세에 보인다. 분류는 공지 / 업데이트 / 이벤트다(설정 – 공지사항 1).
- **계정 정지**: 정지된 계정이 로그인할 때의 안내는 [02 로그인 · 회원가입](02-auth.md#로그인)의 로그인 4에 있다.

## 아직 정하지 않은 것

- **관리자 화면의 세부**: 추후 정한다(관리자 – 기능 목록 1).
- **신고 처리 · 사용자 조치의 상세 화면**: 다음 단계에서 그린다(관리자 – 기능 목록 5).
- **공지 작성**: 메뉴(1)에 "공지 작성"이 있지만 이를 설명하는 항목이 없다. 공지의 분류 · 제목 · 날짜 · 본문은 [10 설정 · 계정](10-settings.md#설정--공지사항)의 공지사항 1과 공지사항 상세에만 적혀 있다.
