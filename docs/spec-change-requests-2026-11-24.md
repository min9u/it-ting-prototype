  - 첫 줄 검사: ^(feat|fix|refactor|test|docs|chore): (?!.*KAN-\d)\S.{0,48}[^.]$
  - 본문: 무엇을 왜 바꿨는지(프론트 PR #37을 명세에 맞추며 비어 있거나 어긋난 곳, 방문자 방명록 삭제 문구는 사용자 확정). docs/spec/README.md "결정이 바뀌면 … 커밋 메시지에 쓴다"
  - 맨 아래 AI 공동 작성 표시(Co-Authored-By, 커밋 규칙 "AI 공동 작성 표시").
  - 서명된 커밋이어야 한다. 내 git 설정(user.name, user.email, 서명)을 바꾸지 말고 --no-gpg-sign, --no-verify 를 쓰지 않는다. 서명이 안 되면 멈추고 docs/commit-convention.md "커밋 서명"을 나에게 안내한다.
- PR은 스킬 pr-create 를 따른다(문서만 바꿨으니 code-review · 빌드 · "한눈에 보기"는 생략).
  - 푸시 전: git fetch origin && git merge-tree --write-tree HEAD origin/dev 로 충돌 확인
  - git push -u origin HEAD  (dev 에 직접 푸시 · 강제 푸시 금지)
  - gh pr create --base dev --title "docs: KAN-<번호> 명세의 빈 문구와 어긋난 곳 수정" --body-file <본문 파일>
  - 본문: "## 무엇을 바꿨나"(항목 번호 · 파일 · 한 줄 요약 표), "## 확인한 것"(지금 문구 확인, 링크 · 번호 확인, 건너뛴 항목), "## 나중에 정할 것"(위 "확인 필요"와 "백엔드 확인 필요"가 있으면 그것)
  - PR은 병합하지 않는다. Codex 리뷰 확인은 pr-create 9단계를 따른다.
