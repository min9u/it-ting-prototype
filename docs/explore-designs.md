# 탐색 화면 디자인 시안 A·B·C·D + 미니맵(전체 마을 지도)

- 날짜: 2026-11-16
- 요청
  1. "지금 탐색 화면 디자인처럼, 다른 땅굴로 이동하는 화면을 여러 디자인으로 만들어 줘."
  2. "미니맵으로 전체 마을에서 땅굴과 두더지가 어디에 위치하는지 확인할 수 있도록 만들어 줘."
- 기준: 지금 탐색 = 시안 A ([explore-field-v3-9.md](explore-field-v3-9.md), 3D 들판 · 구멍 점프). 명세는 Figma 02 F5, 디자인 톤은 03 Screens (`design/figma/` PNG). Figma 호출 없음

## 결론
- 같은 주소 `/burrow/explore` 에서 시안 4개를 바꿔 볼 수 있게 만듦. 위쪽 가운데 어두운 "시안 A · B · C · D" 칩(프로토타입 비교용) 또는 주소 `?design=a|b|c|d`. 고른 시안은 이 탭에서 기억(sessionStorage, 막힌 곳은 메모리)해서 모드 토글 "탐색"·뒤로 가기로 다시 와도 그 시안
- 미니맵은 A·B·C·D 모두에 있음 (D 는 오른쪽 위, 나머지는 왼쪽 아래). A 에서는 3D 카메라가 보는 범위(사다리꼴)와 점프 중인 두더지까지 보여 줌
- **추천: A(3D 들판) + 미니맵을 기본으로, 그래픽 가속이 꺼진 PC 는 B(마을 지도)로 자동 전환하는 쪽.** C·D 는 통째로 쓰기보다 조각(방 단면 미리보기, "잘 맞는 순 + 말 거는 계기")을 A·B 의 안내판·오른쪽 카드·추천에 가져오기를 제안 (아래 "추천안과 이유")

| 시안 | 한 줄 | 주소 | 그리기 |
|---|---|---|---|
| A 들판 점프 | 3D 들판에서 구멍 → 구멍 점프 (지금 디자인) + 미니맵 | `/burrow/explore?design=a` | three.js (기존 holeField) |
| B 마을 지도 | 층 전체를 2D 일러스트 지도로. 두더지가 길을 따라 걸어감 | `?design=b` | SVG 한 장 + 버튼 (3D 없음) |
| C 땅속 굴길 | 단면도. 땅굴 방들이 굴길로 이어져 있고 두더지가 파고 감 | `?design=c` | DOM·CSS (3D 없음) |
| D 이웃 카드 | 나와 잘 맞는 순으로 이웃 땅굴 카드를 넘김 | `?design=d` | DOM·CSS (3D 없음) |

화면 목록(`/screens`) "땅굴" 묶음에 시안별 링크 + 미니맵 크게 보기(`?design=a&map=big`) + 빈 들판(부울경-1층) 링크를 넣음.

## 시안별

### A. 들판 점프 (지금 디자인 + 미니맵)
- 컨셉: 디자이너 3D 핸드오프 v3.9 들판 그대로. 서 있는 구멍의 안내판 → Enter 로 들어감
- 조작: 방향키·WASD = 그 방향 ±45° 가장 가까운 구멍, 구멍 클릭 = 바로 그 구멍, Enter = 입장(어두워짐), 사다리 = 캠퍼스-층. **미니맵에서 땅굴을 누르면 3D 두더지가 그 구멍으로 바로 점프** (`HoleFieldHandle.goSeat`)
- 장점: 03 Screens 의 점토 그림체와 가장 가까움, 걸어 다니는 "동네" 느낌. 새로 더한 미니맵으로 "나는 마을 어디쯤, 누가 어디" 가 보임
- 단점: 한 화면에 구멍 몇 개만 보여서 150자리 층에서 사람 찾기가 느림(미니맵·크게 보기로 보완). 3D 라 첫 진입이 무거움
- 저사양 부담: 큼 (WARP 에서 이미 저사양 묶음). 미니맵은 SVG 라 거의 없음: 자리가 바뀔 때만 요소 2개를 0.8초 옮기고, 두더지 둘레 물결은 3번만 돌고 멈춤(계속 움직이면 미니맵을 계속 다시 그려서)

### B. 마을 지도 (2D 일러스트 탑뷰)
- 컨셉: 층 = 마을 지도. 배치·길·잔디·호박은 3D 와 같은 `fieldLayout150.json` 을 2D 로 그림 → 자리·사다리·구역 규칙이 A 와 1:1 로 같음
- 조작: 땅굴 클릭 = 두더지가 **길을 따라** 걸어감(길 타일을 그래프로 만들어 최단 경로, 0.5~2.4초), 방향키 = A 와 같은 ±45° 규칙, 끌기 = 지도 옮기기, 휠·＋/－ = 확대·축소(커서 기준), "전체"·`0` = 켜진 구역 전체, "나" = 내 두더지로. 걸어가는 동안 두더지가 화면 끝에 가까우면 지도가 따라감
- 위쪽 필터: 모두 · 단골 · 겹치는 관심사 · 접속 중 (맞는 땅굴은 진하게 + 이름표, 나머지는 흐리게). 땅굴마다 같은 관심사 수 배지(2개 이상, 필터 켜면 1개부터), 가까이 보면 드문 취미가 겹칠 때 "✦ 관심사" 표시
- 장점: 사람 찾기가 가장 빠름(한눈에 층 전체 + 필터). 니치 취미 찾기에 강함. 가벼움. 3D 들판과 같은 데이터라 저사양 대체 화면으로 바로 쓸 수 있음
- 단점: 들판 "안에 있는" 몰입감·점토 질감이 약함. 확대가 낮으면 이름표가 숨음(마우스를 올리면 보임)
- 저사양 부담: 작음. 바탕 SVG 는 한 번 그리고 CSS transform 으로 옮김(끄는 동안만 `will-change`), 땅굴은 CSS 변수(`--k` 배율, `--px/--py` 위치)로 자리만 다시 계산 → 끌기·확대 때 React 다시 그리기 없음
- 미니맵: 지도가 확대돼 있을 때 지금 보이는 사각형을 보여 줌. "크게 보기"는 B 에서는 전체 보기로 대신함

### C. 땅속 굴길 (단면도, 가로로 이어짐)
- 컨셉: 땅 위에는 입구(링 색 흙더미 + 자리 번호 팻말), 땅속에는 방(돔 단면)이 굴길에 위·아래로 번갈아 매달린 개미집 모양. 방 순서 = 자리 번호(땅굴을 만든 순서, 02 F5 1)
- 방 단면 미리보기: 그 사람 벽지(3D 땅굴과 같은 규칙: 가장 큰 취향 분류 → 벽지 타일), 관심 분야 소품(분류 이모지), 집주인 두더지(액세서리를 2D 아바타 그림으로), 접속 중 표시, 같은 관심사 꼬리표
- 조작: ←/→ 옆 땅굴로 파고 감(흙 튀김), **↑/↓ 나와 관심사가 겹치는 앞/뒤 땅굴로 건너뜀**, 방·입구 클릭 = 그 방까지 굴길을 따라감(최대 1.7초), 휠·끌기 = 굴길만 둘러보기(두더지는 그대로, "내 두더지로 돌아가기"), Enter 입장. 안내판은 그 땅굴 입구 옆 땅 위에 꽂힘. 사다리는 굴길 시작
- 장점: **들어가지 않고 방을 엿볼 수 있어** 말 걸기 전 부담이 가장 낮음(내향적인 사람). "두더지가 땅굴로 이어져 있다"는 세계관이 가장 잘 드러남
- 단점: 한 줄(1차원)이라 들판의 "가까운 이웃" 개념이 사라짐(미니맵이 보완). 150자리면 굴길이 아주 김
- 저사양 부담: 작음. 화면 근처 방만 그림, 굴길은 SVG 선 하나, 이동은 굴길을 잘게 나눈 점들을 따라 rAF

### D. 이웃 카드 넘기기
- 컨셉: 공간 대신 "나와 잘 맞는 순". 잘 맞는 정도 = 겹치는 관심사마다 1 + 1000/그 관심사 인원(온보딩 땅굴 무드와 같은 식, 드문 취미가 무거움) + 접속 중 조금
- 카드 앞면: 방 단면 미리보기 + 자리, 닉네임·소속·접속 중·단골, 겹치는 관심사(드문 취미 ✦, 인원 툴팁), 관심 분야, **말 거는 계기**(드문 취미가 겹치면 "나랑 같은 드문 취미, 약 N명뿐", 아니면 겹치는 관심사, 없으면 그 사람 Q&A 하나). 뒷면: 자기소개 + 질문 3개와 답(추천 결과 카드처럼 뒤집기)
- 정렬: 잘 맞는 순 · 접속 중 · 단골 · 자리 순. 맨 앞 카드는 내 땅굴(내 땅굴로 돌아가기 = 맨 앞으로). 처음은 가장 잘 맞는 이웃
- 조작: ←/→ 넘기기(끌어서 넘기기도), ↑/↓ 뒤집기, Enter 놀러가기. 오른쪽: 미니맵("이 땅굴이 마을 어디쯤") + 다음 차례 4명
- 장점: 니치 매칭·말 걸 계기가 가장 분명. 가장 가벼움
- 단점: "들판을 돌아다닌다"(02 F5 1)는 경험이 거의 없음. 오른쪽 주인 카드 대신 큰 카드라 다른 땅굴 화면과 배치가 다름. 오늘의 추천 친구와 역할이 겹침
- 저사양 부담: 거의 없음

## 미니맵 (`app/src/screens/burrow/Minimap.tsx`)
- 층 하나 = 마을. 배치는 3D 와 같은 `fieldLayout150.json`, 사람은 `fieldOf(floor)` (자리 → 주인, 내 자리, 켤 구역 수)
- 그리는 것: 켜진 구역(흙), 안 켠 구역(잔디색), 잔디 덩어리, 길(옅게), 땅굴(링 색 점 + 가운데 구멍), 빈 자리(옅은 점), 내 땅굴(분홍 + 집), 사다리, **내 두더지**, **지금 화면에 보이는 범위**, 접속 중(초록 점) · 단골(노란 별)
- 작은 지도는 켜진 구역 + 둘레 7m 에 맞춤 (서울-2층처럼 세로로 긴 마을은 범례를 지도 오른쪽에). 화면이 낮으면 지도도 낮아짐
- 내 두더지: 자리가 바뀌면 두 구멍 사이를 부드럽게 옮겨 감. A 에서는 점프 리듬 그대로(두더지 0~0.82초 + 살짝 커졌다 작아짐, 보이는 범위는 0.42초 뒤 0.4초). B 는 길을 따라 걷는 위치를 그대로 받음(`handleRef.setMole`)
- 보이는 범위(A): 카메라 목표점 = 서 있는 구멍을 켜진 구역 camRect 합집합 안으로 제한한 점(holeField.ts 와 같은 계산). 사다리꼴은 FOV 32.3° · 45° · 12m 로 실제 화면 비율·오른쪽 카드 위치(focusX)·카드가 가린 폭까지 넣어 계산. 16:9 · 가운데 · 안 가림이면 핸드오프 값(아래 9.6 · 위 17.4 · 앞 3.8 / 뒤 6.9m)과 같음
- 마우스를 올리면 닉네임(+접속 중·단골), 누르면 그 땅굴로 바로(A: 3D 점프, B: 걸어감, C: 파고 감, D: 그 카드). 사다리를 누르면 캠퍼스-층 고르기
- 접기/펼치기(이 브라우저에 기억 `digul.minimap`), **크게 보기 = 전체 마을 지도 팝업**: 층 전체(안 켠 구역은 "아직 비어 있는 구역"), 필터(모두 · 단골 · 겹치는 관심사 · 접속 중 — 맞는 땅굴만 진하게 + 이름표), 목록(겹치는 관심사는 잘 맞는 순)과 "이동", 범례. 팝업이 열려 있는 동안 방향키·Enter 가 뒤의 A 화면으로 가지 않게 막음(Esc·Tab 은 그대로)
- 배치: A·B·C 는 왼쪽 아래 "내 땅굴로 돌아가기" 위(왼쪽 위 버튼 3개 · 안내판 · 모드 토글과 안 겹침), D 는 오른쪽 위

## 추천안과 이유
1. **기본은 A + 미니맵.** 디자이너 3D 핸드오프(v3.8·v3.9)와 03 Screens 그림체가 이미 이 방향이고, 02 F5 1 "들판을 돌아다니며" 와 가장 맞음. A 의 약점(한 화면에 몇 개만 보여서 찾기 느림)은 미니맵 + 크게 보기 필터로 상당 부분 풀림
2. **저사양(그래픽 가속 꺼짐)은 B 로 자동 전환** 제안. 같은 배치·자리·규칙이라 사용자가 보기에 "같은 마을의 지도 보기" 이고, 3D 를 안 써서 WARP PC 에서도 가볍다. 감지는 이미 있는 `graphicsTier()`
3. C·D 는 조각을 가져오기
   - C 의 **방 단면 미리보기**(`RoomPeek`)를 A·B 안내판이나 오른쪽 카드 위에 → 들어가기 전에 방을 엿봄(내향적인 사람 · 말 걸기 부담)
   - D 의 **잘 맞는 순 + 말 거는 계기**를 오늘의 추천 친구 결과나 오른쪽 카드에 → 니치 취미 매칭이 눈에 보임
   - D 를 통째로 쓰면 "들판을 돌아다닌다"는 명세 1과 멀어지고, C 를 통째로 쓰면 "가까운 이웃" 개념이 사라짐
4. 팀이 확인해 줄 것: B 를 저사양 대체로 쓸지, 방 미리보기 그림을 어디에 둘지, "드문 취미" 기준(지금 400명 미만, 목 데이터 기준 임시값), 말 거는 계기 문구

## 남은 것
- 실제 브라우저에서 느낌 보기: B 걷기 속도, C 파고 가기 속도, D 끌어 넘기기 (헤드리스는 rAF·전환이 느려 리듬을 못 봄)
- 실제 SSAFY PC(WARP)에서 B 를 저사양 대체로 썼을 때 끌기·확대 프레임
- 방 미리보기는 2D 근사(벽지 타일 + 분류 이모지 + 2D 두더지). 3D 땅굴 가구와 1:1 은 아님. 실제 방 썸네일(렌더 이미지)을 쓰려면 서버나 미리 굽는 과정이 필요
- B·C·D 의 화면 읽기 프로그램 지원은 기본(버튼·라벨)까지만. 좁은 화면(태블릿 이하)은 PC 전용 정책이라 따로 맞추지 않음
- 미니맵·시안 칩은 아직 팀 아티팩트에 배포하지 않음 (메인이 합친 뒤 배포)
