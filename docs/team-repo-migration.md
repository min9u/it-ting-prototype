# 팀 리포(it-ting-team/it-ting)로 프론트엔드 옮기기 계획 (2026-11-22)

- 요청: "작업이 끝나면 it-ting 깃헙에 이전까지 해온 프론트엔드 개발을 통째로 옮기려고 해 가능해? 그러면 커밋 한번에 하는게 좋을까 여러개의 단위로 커밋하는게 좋을까?"
- 이어서 결정: "Next.js 로 하자. 그리고 커밋을 5-8 개보단 더 늘리자. 예를 들어 feat: 인증,온보딩,땅굴,탐색 화면 추가를 하나하나씩 나눠서 커밋당 책임을 좀 나누는게 좋아보여."
- 순서: [API v1 맞추기](backend/api-v1-alignment.md)를 이 리포(Vite)에서 끝낸 뒤 → Next.js로 옮기면서 팀 리포 `frontend/`에 넣는다

## 결정
1. **프레임워크: Next.js** (팀 리포 `AGENTS.md`의 `frontend/` = Next.js에 맞춤). App Router, 화면은 거의 다 클라이언트 컴포넌트(`'use client'`), three.js·브라우저 전용 코드는 `dynamic(..., { ssr: false })`
2. **커밋: 화면·기능 하나에 커밋 하나** (아래 목록, 약 25개). PR 하나에 담음
3. 예전 이력(이 리포 커밋 308개)은 옮기지 않음: `dev`는 서명된 커밋만 병합되고, 다른 팀원 커밋 86개는 대신 서명할 수 없고, 메시지 형식도 팀 규칙과 다름. PR 본문에 이 리포 링크를 남김

## 팀 리포 규칙 (옮길 때 지킬 것)
- 브랜치 `chore/fe/KAN-<번호>-<설명>` (Jira 번호 필요) → PR → `dev`. `dev`·`main` 직접 푸시 금지
- 커밋 제목 `<유형>: <설명>` (한국어 50자 이내, `추가`·`수정`·`삭제`로 끝, 마침표·티켓 번호·영역 금지). 검사식 `^(feat|fix|refactor|test|docs|chore): (?!.*KAN-\d)\S.{0,48}[^.]$`
- 한 커밋 = 한 목적, **커밋마다 빌드·테스트 통과**
- **모든 커밋 서명** (SSH 서명 키. 이 맥은 아직 설정 안 됨 → 사용자가 팀 문서 `docs/commit-convention.md` "커밋 서명"대로 설정·GitHub 등록)
- AI가 함께 쓴 커밋은 맨 아래 `Co-Authored-By`
- 로컬 CORS 출처는 `http://localhost:3000` (Next 기본 포트와 같음)

## Next.js로 바꿀 때 할 일
- 라우트 48개(`App.tsx`, react-router) → `app/` 폴더 구조. 주소 파라미터·쿼리는 Next 훅으로
- 공유 빌드(아티팩트, 해시 라우터)는 Next로 옮기지 않고 이 리포에 남김
- 환경 변수 `VITE_*` → `NEXT_PUBLIC_*`. 읽는 곳은 `lib/env.ts` 한 곳으로 모음 (API 작업자에게도 같은 규칙)
- Vite 프록시 → Next `rewrites` (`/api/v1` → 백엔드)
- glb·텍스처 등 에셋 → `public/` 또는 import, Draco 해독기 경로 확인
- CSS Modules·토큰은 그대로 씀. 폰트(Pretendard)는 `next/font/local` 검토
- vitest 단위 테스트는 그대로, 화면 스모크는 `next build && next start` 대상으로 바꿈

## 실험실: 로컬에서만 (2026-11-22 결정)
- 요청: "실험실은 로컬에서 실행할 시에는 넣고, 배포할시에는 넣지 않는 게 가능할까?" → 가능. 코드는 옮기되 **배포 빌드에는 아예 안 들어가게** 함
- 대상: `/lab/style`(땅굴 다양성), `/lab/rooms`, `/screens`(화면 목록), `/dev/crash`, 🧪 저사양 실험실 패널(`LowLab`), 목 서버 손잡이 배지
- 방법
  - 실험실 페이지 파일 이름을 `page.lab.tsx`로 하고 `next.config`의 `pageExtensions`에 `lab.tsx`를 **켤 때만** 넣음 → 끄면 그 주소가 빌드에 없음(404), 코드도 안 묶임
  - 화면 안에 끼는 패널은 `if (LABS)`로 감싸고 `next/dynamic`으로 불러옴. `LABS`는 빌드할 때 정해지는 상수라 꺼진 빌드에서는 코드가 빠짐
  - 켜는 기준은 `NODE_ENV` 대신 환경 변수 `NEXT_PUBLIC_LABS=1` (`next dev`에서는 기본 켬). 그래야 나중에 테스트 서버에서만 켜는 것도 가능
- 확인: 배포 빌드 뒤 `/lab/style`이 404이고, 빌드 결과물에 실험실 코드 문자열이 없는지 검사하는 스크립트를 CI에 넣음
