## 판단한 것

1. **#102 · #103 (알림 팝업 안에서 모임 참여 요청 · 채팅 요청을 수락 · 거절하는 화면)은 만들지 않았다.** 11-13 메타데이터에는 #101(팝업 안 탭 + 요청 줄을 누르면 팝업 안이 요청 목록으로 바뀜) · #102 · #103이 있었지만, 11-16 명세 스크린샷(최신)에서는 F9가 "팝업 / 팝업 · 요청 없음 / 알림" 세 화면으로 바뀌었고 요청 줄은 "팝업을 닫고 신청 관리 / 채팅 › 요청 › 받은 요청으로 이동, 수락과 거절은 거기서 한다"로 적혀 있다. 최신 02 명세를 따랐다
2. **차단 관리는 넣었다.** 11-16 F10 스크린샷 10장에는 차단 관리가 없지만(메뉴 그룹도 "알림"), 다른 화면(F7 · F8 "더 보기 › 신고 / 차단")에 차단이 있어 해제할 곳이 필요하다. 11-13 메타데이터의 문구와 메뉴 그룹 이름 "알림 · 차단"을 썼다
3. 모임 참여 요청 숫자: 모임 상세의 신청 관리 팝업이 자기 화면 안의 목 데이터(하린 · 도윤 · 솔)를 써서, 같은 세 명을 `meetupRequestStore`에 두었다. 모임 쪽 저장소가 생기면 `setMeetupApplicants(meetupId, names)`로 넣으면 팝업이 따라 바뀐다. 지금은 신청 관리에서 수락 · 거절해도 팝업 숫자는 그대로
4. 알림 설정에서 끈 종류: 명세는 "새 알림과 GNB 빨간 점에 나타나지 않는다". 프로토타입은 받은 시점을 구분하지 않으므로 끈 종류의 알림은 팝업 · 알림 화면 목록과 빨간 점에서 모두 뺐다. 다시 켜면 다시 보인다
