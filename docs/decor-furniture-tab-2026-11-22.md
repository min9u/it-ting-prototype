가구 탭 (명세 04 "땅굴 – 꾸미기 모드 · 가구 탭", 00 공통 5)
- 세부 관심사 칩: 고를 수 있는 내 관심사만(90개 중 57개). 한 단어뿐인 33개는 가구 고정이라 칩에 안 나옴
- "○○ 가구 고르기 · n개 중 1개" 카드(썸네일 + 가구 이름). 처음엔 맨 앞 단어, 고르면 땅굴에 바로 놓임(저장 전에도), 지금 고르는 가구는 점선으로 가리킴
- 예외 둘은 데이터(`words.length`)로 이미 처리: "액세서리/기타"는 가구 모델 1개라 고정, "곤충/파충류/기타"는 곤충·파충류 중 고르기
- 저장하기: 바뀐 것만 저장(두더지 = `PATCH /me/mole`, 가구 단어 = 목 서버). 둘 다 끝나야 내 땅굴로 돌아가고 실패하면 꾸미기에 그대로 있음. 바뀐 게 있을 때 취소는 저장 전 취소 확인(00 공통 18)
- 내 정보 수정에서 관심사를 바꾸면 뺀 관심사의 단어는 지우고 그대로 둔 것은 유지, 새로 넣은 것은 맨 앞 단어(목 서버 `updateProfile`)
- 방문자 뷰도 주인이 고른 가구를 보여 줌(`UserBurrowDto.furniture` → `BurrowVM.furniture` → `VisitBurrow`)
- **구현하지 않은 것**: 고른 단어의 가구가 놓일 자리가 없을 때의 처리·안내(명세 open-issues "정하지 않음")

## 단어 저장은 목 서버에만 (명세에 없음)

백엔드 API 명세에는 가구 단어를 저장·조회하는 칸이 없다(`docs/api/04-my-burrow.md` "방을 꾸미는 값을 저장하는 API는 없다", 계정 DB `user_interest`도 가구를 저장하지 않음). 그래서:

- 목: `MyBurrowDto.furniture`(내 땅굴) · `UserBurrowDto.furniture`(남의 땅굴, 내 것만) · `burrowApi.updateFurniture`(PATCH 흉내) · `useUpdateFurniture`. 값은 `data/myBurrow`의 `getMyFurnChoice`(세부 관심사 id → **한글 단어**, 맨 앞 단어는 저장 안 함)
- 실제 모드: `real.updateFurniture`는 **501 `NOT_IMPLEMENTED`로 실패**(저장 버튼이 "가구를 저장하지 못했어요" 토스트). 성공한 척하지 않음. 조회 응답에 `furniture`가 없으면 빈 값 = 모두 맨 앞 단어
- 백엔드에 요청할 것은 `app/src/api/burrow/PENDING`의 주석에 적어 둠(요청은 사용자가 따로 함)

## 정할 것 / 질문

1. **백엔드**: 가구 단어 저장 API와, 내 땅굴·남의 땅굴 조회 응답의 `furniture`(사용자 요청 예정)
2. **백엔드와 정할 것**: 저장 형태를 지금처럼 한글 단어로 할지, 영어 코드 표를 만들어 코드만 저장할지(DB 설계 G4는 코드 저장 제안). 코드 표가 필요하면 57개 소분류의 단어 코드 목록은 프론트가 만들 수 있음
3. **기획**: 고른 단어의 가구가 놓일 자리가 없을 때(명세 미정). 지금은 아무것도 안 함
4. **사용자(Figma 대조)**: 가구 탭 시안(711:7994)의 칩·카드가 명세와 같은지, 꾸미기 안내 말풍선 문구(지금 "내가 직접 방을 꾸밀 수 있어요. / 다양한 가구들을 사용해 보세요!", 명세엔 문구 없음)
5. 두더지 손 아이템 이름 "소품"(`MoleAvatar` 부위 라벨)은 방 가구가 아니라 두더지 아이템이라 그대로 둠(화면에 표시되지 않음)
