## 3. 백엔드 · API 영향
- 명세 API는 `GET/POST /api/v1/me/daily-recommendation`. 앱의 api 초안은 `POST /me/recommendations/today` 로 이름이 다르고, 앱의 설정 API(`/me/recommend-setting`)는 **없어짐** → `docs/backend/api-draft.md` 에 표시.
- POST 본문: `{ campusFloorId, generation }`. 오늘 이미 받았으면 본문을 보지 않고 저장된 결과로 200. 서버가 하는 일(후보 · 단골 제외 · 횟수 · 무작위)은 명세 `docs/api/05-explore-visit.md` 와 앱의 목이 같은 순서.
- ERD: `recommend_setting*` 테이블 필요 없음(`docs/backend/erd-gaps.md` Q9 해소). 필요한 것은 `daily_recommendation`, `daily_recommendation_member`(횟수를 세려고 지난 날 결과도 지우지 않음).
- 방명록: 자동 삭제 배치 없음. 신고 3명 숨김은 서버(`POST /reports` 의 targetType `GUESTBOOK`). 앱은 숨겨진 글을 받지 못하므로 `reporters` 는 목 전용.
- 땅굴 조회의 대화 상태 `chat.status`: `CHATTING · REQUEST_SENT · REQUEST_RECEIVED · NONE`. 앱은 지금 `chatRoomId` · `pendingRequestId` 로 같은 3상태를 가리킴. `REQUEST_RECEIVED`("이미 나에게 요청한 사람입니다" 토스트)와 "내가 거절한 요청이 남아 있으면 요청 시 바로 대화방"은 **아직 구현 안 함**(이번 요청 범위 아님).

## 5. 새 학기 안내 (이번엔 구현하지 않음, 명세 요약)
명세 `05-explore-visit.md` "땅굴 메인 – 새 학기 안내" (Figma `1465:15925`, 시안 노드 `1466:16137`).
- **언제**: 새 학기 들판이 열린 뒤, 이번 학기의 캠퍼스 · 층을 아직 고르지 않은 사람이 로그인해서 처음 보는 화면 위에 뜸. API는 `GET /me` 의 `nextStep = NEW_TERM`.
- **무엇**: 새 학기 이름(예: 2027 상반기)을 알리고 이번 학기의 캠퍼스와 층을 **반드시** 고르게 함. 고르기 전에는 닫을 수 없고 다른 화면도 못 씀. 지난 학기에 고른 캠퍼스가 처음에 선택돼 있음.
- **고르는 방법**: 캠퍼스 고르기 → 그 캠퍼스의 층 목록. 방법은 캠퍼스-층 고르기(탐색)의 2~4와 같음(캠퍼스 줄, 층 번호 검색, 층 목록 · 선택 · 땅굴 없는 층은 "비어 있음").
- **"이 층으로 정하기"**: 층을 골라야 눌림. 누르면 내 땅굴이 그 캠퍼스 · 층의 **이번 학기 들판으로 이사**(방명록 · 단골 · 방의 모습은 그대로, 위치와 프로필의 캠퍼스 · 층만 바뀜). 지난 학기 들판의 자리는 비고 입구가 남지 않음. 완료 토스트. API `POST /me/burrow/move`(새 학기를 고르기 전에도 호출 가능).
- **닫기 없음**: "나중에 하기" · ×도 없고 바깥 클릭 · Esc로도 안 닫힘. 고른 뒤에는 다시 안 뜨고 그 학기의 캠퍼스-층은 내 정보 수정에서 바꿈.
- **고르지 않은 사람**: 지난 학기 들판에 땅굴이 그대로 남고 오늘의 추천 친구에는 나오지 않음(앱의 `recommendPool` 이 이번 학기 들판에서만 뽑으므로 이미 맞음).
- **만들 때 알아 둘 것**: 앱에는 학기가 이번 학기(`CURRENT_TERM`) 하나뿐이고 내 땅굴 이사(`MY_FLOOR`) 상태가 고정이라, 새 학기를 열어 보려면 목 데이터에 "다음 학기"와 "아직 안 고름" 상태가 필요. 캠퍼스-층 고르기 팝업(`FloorPickerModal`)을 `닫기 없음` 모드로 다시 쓰는 것이 가장 가까움.
