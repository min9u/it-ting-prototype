# 렌더링 개선 실험 2: 그래픽 가속을 끈 크롬 (2026-11-16)

- 요청: "크롬에서 그래픽(하드웨어 가속)을 끈 상태로 성능을 측정해 보고, 성능을 높일 수 있는 후보들을 다양하게 세워서 실험해 봐."
  - 추가 요청 (같은 날): 탐색 들판도 땅굴 "S 방은 선명하게"처럼 **배경은 최대한 선명하게, 움직이는 두더지만 해상도를 조금 낮추는** 방향. 점프 카메라 0.4초는 따로 처리, 배경을 다시 찍는 비용(멈춤)도 잴 것. 둘 다 선명해도 괜찮으면 그쪽이 더 좋음. 후보마다 **화질(GPU 고화질 대비 PSNR·SSIM)과 성능**을 숫자로 → `explore/gpu/results/field-tradeoff.json`
- 이전 실험: [rendering-experiments.md](rendering-experiments.md) (땅굴 첫 진입), [gpu-lowspec-ideas.md](gpu-lowspec-ideas.md) (저사양 실험실 A~S), [gpu-fallback-research.md](gpu-fallback-research.md)

- **탐색 들판 저사양 기본값 = S1_RA** (A + P + 예열 + R 0.6 + S 1배 비동기). 선명한 배경 준비가 두 번 0.2초를 넘으면(느린 PC) 그 장면에서는 S 를 끄고 A_R 로 내려감
- 둘 다 선명(P1_R, 캔버스 1배)도 16스레드에선 점프 52.6fps 로 쓸 만하지만, 2코어에선 19fps 로 절반이 돼서 기본으로 하지 않음 (아래 4번 표)

## 1. 측정 조건
- 이 PC: i7-11700(8코어 16스레드), RTX 5060 Ti 가 있지만 크롬 가속을 끈 조건. 크롬 157 헤드리스 1920×1080(화면 1904×985), 새 프로필의 `Local State` 에 `hardware_acceleration_mode.enabled=false`
- 렌더러 문자열: **`ANGLE (Microsoft, Microsoft Basic Render Driver (0x0000008C) Direct3D11 vs_5_0 ps_5_0, D3D11)`** = WARP (헤드리스에서도 WARP 로 나와서 창 있는 크롬은 안 씀). 화질 기준 GPU: `ANGLE (NVIDIA, NVIDIA GeForce RTX 5060 Ti ... D3D11)`
- 대상: 공유 빌드 (`npm run build:share` → `vite preview --outDir dist-share --port 5301`), 해시 라우팅. 로그인 검사 꺼짐(LOGIN_FREE)
- 3번 재서 중앙값. 2코어 = 크롬을 CPU 2개에 묶음(`AFF=3`, 더 약한 PC 감각)
- **WARP 의 CPU 사용은 GPU 프로세스에서 일어남** (여러 스레드로 그림). 그래서 "그리기 CPU" = GPU 프로세스 CPU 사용률(100% = 코어 하나), 페이지(메인 스레드)는 "렌더러" 프로세스. 화면이 버벅이는지는 페이지 rAF fps·긴 작업·rAF 최악 간격으로 봄

### 후보 설명
- **A 배경 한 번**: 움직이지 않는 들판(땅·구멍·길·잔디·작물·꽃·울타리·사다리)을 렌더 타깃(HalfFloat 색 + 깊이)에 한 번 그리고, 매 프레임은 붙인 뒤 움직이는 층(layer 1: 두더지·발밑 그림자·하이라이트 링)만 (`staticBackdrop.ts`, 땅굴·옛 밭과 같은 방식). **P** 두더지·링 둘레 사각형만 다시 그림. 카메라가 움직이는 0.4초와 패널 이동 중에만 전체를 그리고, 멈추면 다시 찍음
- **R 이동 중 저해상도** (`panscale`): 카메라가 움직이는 동안 배경을 캔버스의 0.6배(= 0.33배) 렌더 타깃에 그려 늘려 붙이고, 도착한 뒤 두더지가 튀어 올라 **조용해질 때까지 그 그림을 그대로** 씀 → 다시 찍는 멈춤이 점프 동작 중이 아니라 가만히 서 있을 때 생김
- **S 배경 선명**: 땅굴 S 와 같은 방식. 배경만 1배(`fss=1`) 또는 1.5배 슈퍼샘플(`fss=0`, 땅굴과 같은 식)로 한 번 그려 뒤 2D 캔버스에 깔고, WebGL 캔버스는 투명하게 지운 뒤 배경 깊이만 써서 두더지·링만 0.55배. **비동기 읽기**(`fsasync`): 고해상도 그림을 GPU 버퍼(PBO)로 복사만 걸어 두고(fence) 다 되면 다음 프레임에서 꺼내 2D 캔버스로 → 메인 스레드가 그림을 기다리지 않음
- **P1 전체 1배**: 캔버스 자체를 1배로 (두더지도 선명). P1AA 는 배경 렌더 타깃을 2배로 그려 붙일 때 2×2 평균(안티앨리어싱)

### 읽는 법
- **A 만으로 성능은 거의 다 얻음**: 점프 28 → 52fps, 가만히 그리기 CPU 214 → 54%, 첫 진입 멈춤 0.78 → 0.18초. 화질도 기준(base)보다 좋아짐(배경 SSIM 0.972 → 0.988) — 같은 0.55배인데 기준은 늘려 붙일 때 흐려지고 A 는 덜 흐려서
- **R** 은 화질 손해 없이(멈춰 있는 그림은 같음) 카메라 이동 fps 를 40 → 55, 2코어 13.8 → 18.1 로
- **S** 는 배경을 GPU 수준 가까이 선명하게(가장자리 SSIM 0.924 → 0.952). 대신 점프가 끝날 때마다 1배 배경을 한 번 그리는 비용이 있음: 그 자리에서 읽으면(S1_R) 메인 스레드가 16스레드 0.09~0.12초, 2코어 0.34~0.51초 멈춤. **비동기 읽기(S1_RA)로 16스레드 0.05~0.07초**, 점프 fps 도 A_R 보다 높음(56.9). 2코어에선 그림 자체가 늦게 나와(약 0.3~0.4초) 장면이 그만큼 밀림
- 1.5배 슈퍼샘플(S, S_RA)은 1배(S1)보다 숫자가 오히려 낮음(가장자리 0.933 vs 0.952): 2D 캔버스로 줄일 때 조금 흐려져서 GPU 의 MSAA 와 더 달라짐. 눈으로는 계단이 없어 더 매끈해 보이지만 비용이 2배라 1배를 고름
- **P1(둘 다 선명)** 은 두더지 SSIM 0.953 → 0.959 로 조금 나음. 16스레드에선 R 을 붙이면(P1_R) 점프 52.6fps 로 괜찮지만 가만히 CPU 62%, 2코어는 19fps 로 절반. P1AA 는 화질 최고(배경 0.995·가장자리 0.964)지만 배경 다시 찍기가 무거워 끊김 0.3초
- 환경맵 끔(A_noenv)은 빨라지지만(첫 진입 0.13초) 색이 달라짐(배경 PSNR 37.8 → 23.1) → 버림
