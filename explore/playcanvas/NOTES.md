# PlayCanvas 실험 노트

- 엔진: PlayCanvas engine 2.23.3 (`playcanvas.min.mjs`, jsDelivr ESM). Editor 없이 `pc.Application` + 직접 만든 캔버스
- 파일: `field.html` (탐색하기 밭), `room.html` (땅굴 방), 기준 이미지 `ref-field.png`, `ref.png`, 회차별 스크린샷 `shots/`
- 해시: `#3d`, `#ref`, `#bare`, `#bare-mole`, `#bare-ref-mole`. 디버그용 꼬리표 `&np`(후처리 끔), `&ns`(그림자 끔), `&noenv`, `&nosun`, `&pcf`(field만)
- 스크린샷 크기: field `#bare` 1440×897, `#bare-mole` 600×660 / room `#bare` 1272×954, `#bare-mole` 530×560
- 확인: `node explore/serve.js 5192` → `http://127.0.0.1:5192/playcanvas/field.html#bare`
- 헤드리스 Edge(swiftshader)에서 CameraFrame(SSAO·HDR 타깃)까지 그대로 동작. 한 장 찍는 데 약 40초

## 쓴 PlayCanvas 기능
- `CameraFrame`: SSAO(COMBINE), 톤매핑, 색보정, 비네트, MSAA 4x
- `EnvLighting.generateLightingSource/generateAtlas`: 캔버스에 그린 그라데이션(하늘/풀밭, 방은 크림/테라코타)을 환경광으로 구움
- 방향광 PCSS 소프트 그림자 (`SHADOW_PCSS_32F`, `penumbraSize`)
- 인스턴싱: 꽃(데이지·분홍꽃)·덤불 3종·돌·흙덩이를 `MeshInstance.setInstancing` 으로 (종류별 드로우콜 1번)
- 직접 만든 지오메트리: 회전체(lathe), 튜브, 해석적 법선의 둥근 상자, 원판. 여러 조각을 꼭짓점 색과 함께 한 메시로 합치는 `Geo`
- `camera.calculateProjection` 으로 비대칭 프러스텀 → 두더지 영역만 확대 렌더(`#bare-mole`)
- 구도 맞추기: 원본 화면 좌표(px)를 땅 위치로 역계산하는 `ground(sx, sy)`, 그 자리의 px→m 비율 `perPx()` 로 둔덕·표지판·앞쪽 소품을 원본 픽셀 위치에 맞춰 배치
- 색 비교: 임시 페이지로 원본과 스크린샷의 같은 지점 평균색을 뽑아 비교 (작업 후 삭제)

## 탐색하기 밭 (field) 회차 기록
| 회차 | 원본과 달랐던 점 | 고친 것 |
|---|---|---|
| r1 | 하늘이 회색 안개, 지평선이 너무 높음, 앞쪽 꽃·덤불이 너무 크고 많음, 색이 너무 진함, 두더지 볼이 아래쪽에 붙음 | 하늘 돔 색, 안개 줄임, 앞쪽 소품 크기 0.55배, 흩뿌리기는 두더지 뒤부터, 색 낮춤 |
| r2 | 하늘이 사라지고 초록 언덕이 화면 위까지 (먼 언덕 높이 함수 오류) | 지평선을 원본처럼 가운데가 살짝 낮은 볼록한 곡선으로 (가운데 y≈221, 양끝 y≈193) |
| r3 | 볼이 눈 위로 올라감 (uv v가 높이가 아니라 단면 점 순서), 두더지가 원통형, 정면이 전부 어두움 | 몸통 uv v = 높이/H, 몸을 아래가 넓은 탄환형으로, 정수리 얼룩 지움 |
| r4~r5 | 정면을 향한 면(표지판·두더지 아랫배)이 원본보다 훨씬 어두움 | 원인: SSAO 반경이 월드 단위인데 40을 줌 → 0.6으로. 한 번에 밝아짐 |
| r6 | 그림자가 안 보임, 하늘이 회색빛 | 확인 결과 그림자는 그려지는데 환경광이 너무 세서 묻힘. NEUTRAL 톤매핑+채도 보정이 하늘을 탁하게 해서 LINEAR로 |
| r7~r8 | 잔디·둔덕 꼭대기가 과노출, 덤불이 형광, 두더지 꼭대기가 뾰족 | 햇빛/환경광 비율 조정, 색 낮춤, SSAO를 COMBINE으로(접지 그림자), 돔 지수 조정 |
| r9 | 둔덕이 화산처럼 평평한 테 | 도넛 단면을 새로 (바깥 볼록 어깨 + 둥근 테 + 가파른 안쪽), 울퉁불퉁 줄임 |
| r10 (최종) | 구멍 안이 그냥 검정, 두더지가 원본보다 길쭉, 오른쪽 뒤 표지판 기울기 반대 | 안쪽 벽을 테→갈색→검정 그라데이션, 두더지 폭 늘리고 키 줄임, 기울기 반대로 |

최종: `shots/final-field.png`, `shots/final-mole.png` (원본 같은 영역: `shots/ref-mole.png`)

### 항목별 판정 (최종)
- 가까움: 하늘 그라데이션과 지평선 곡선, 잔디 색(원본 #bedb63 / 최종 #b8de63), 구도(둔덕 3개·표지판 3개·두더지 위치와 크기), 두더지 실루엣·눈·볼·코·손·발 배치, 꽃·덤불 분포
- 부분: 둔덕(도넛 모양과 어두운 구멍은 맞음, 원본의 매끈한 표면과 구멍 속 깊이감은 덜함), 덤불 색(앞쪽 덤불이 원본보다 밝은 연두), 그림자(부드럽지만 원본보다 옅음), 두더지 질감(얼룩은 은은하게 맞췄지만 원본의 미세한 점토 결은 없음)
- 차이 큼: 원본 렌더러의 간접광 번짐, 미세한 표면 요철

## 땅굴 방 (room) 회차 기록
three.js 시험판(`explore/3d/room.html`)의 배치·카메라를 그대로 옮기고, 두더지는 밭 장면의 `buildMole`을 재사용.
| 회차 | 원본과 달랐던 점 | 고친 것 |
|---|---|---|
| r1 | 장면 전체가 위로 치우침(돔 꼭대기가 잘림), 모든 게 연어색으로 물듦, 초록 소품이 노랗게 | 카메라 높이·주시점 +0.6, 환경광·조명 색을 덜 따뜻하게 |
| r2 | 벽이 진한 주황빛, 두더지가 원본보다 크고 영사기 릴이 두더지 앞을 가림 | 벽·갈비뼈·마루 색을 베이지 쪽으로, 조명 거의 흰색 |
| r3~r4 | 방 두더지는 원본에서 볼터치가 거의 없고 코가 진한 산호색, 몸이 더 매끈 | `buildMole`에 털색·코·콧구멍·손·볼 세기 옵션 추가, 크기 1.62→1.5, 영사기를 오른쪽으로 |
| r5 (최종) | 몸 얼룩이 너무 보임 | 얼룩 세기 옵션(0.35), 두더지를 조금 뒤로 |

최종: `shots/final-room.png`, `shots/final-room-mole.png` (원본 같은 영역: `shots/ref-room-mole.png`)

### 항목별 판정 (최종)
- 가까움: 돔 실루엣·갈비뼈·단면 테두리, 가구 배치와 비율, 두더지 모양
- 부분: 색감(벽이 원본보다 살짝 분홍), 구석 그림자(SSAO), 가구 모서리 곡면
- 차이 큼: 간접광 번짐(GI), 원본 가구의 세밀한 디테일(책·병·악기 모양)

## PlayCanvas가 three.js보다 쉬웠던 것 / 어려웠던 것
- 쉬움: CameraFrame 한 객체로 SSAO·톤매핑·비네트·색보정 (three.js는 EffectComposer에 패스를 직접 이어 붙임). 환경광 굽기(EnvLighting)가 캔버스 그라데이션 한 장으로 끝남. 인스턴싱이 한 줄. 비대칭 프러스텀 지정이 쉬움
- 어려움: Lathe·Tube·RoundedBox·Extrude 같은 지오메트리 헬퍼가 없어 전부 직접 작성. SSAO 반경이 월드 단위라 기본값(30)으로는 장면이 통째로 어두워짐. 방향광은 엔티티의 -Y 방향이라 three.js(위치→타깃)와 감각이 다름. 첫 프레임에 그림자를 확실히 넣으려고 두 번 그림. 빌드가 무거움(min 약 2.5MB, gzip 약 640KB vs three.js 약 170KB)

## 안 된 것 / 남은 것
- 필름 그레인은 CameraFrame에 없어 뺐음 (필요하면 커스텀 셰이더 패스)
- 원본의 피사계 심도(먼 곳 흐림)는 CameraFrame `dof`로 가능하지만 헤드리스 확인 시간이 길어 켜지 않음
- 방 장면은 three.js 시험판을 거의 그대로 옮긴 것이라 가구 디테일 한계도 같음
