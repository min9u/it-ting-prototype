## 3. 개발팀이 할 일
1. `room_base_v3.glb` → **`room_base_v3_1.glb`**(`glb_compressed` 는 `_draco_webp`)로 교체. 노드 이름은 v3 와 겹치는 것 그대로, 새 5개가 늘었다. 카탈로그에 type base 행 5개 추가(`cabinet_low`, `floor_lamp`, `floor_plant_big`, `rug_front_oval`, `rug_right_small`).
2. **두더지가 걷는 길**: 위 2번 표의 수납장·조명·큰 화분 발자리(러그 제외)를 발자리 목록(`itemFeet` 에 해당)에 넣기. 몸 반지름 0.36m 로 돌아 걷는 계산은 그대로.
3. `slots_v3_8_1.json` 으로 교체. 새 칸은 `kind` 가 `floor_prop`(바닥) / `table_top`(원탁 위). `model_scale` 을 모델 크기에 곱해서 놓는다. 원탁 칸은 `pos_three[1]` = 0.39 높이.
4. **작은 소품 배정**: `PLACEMENT_v3_8_1.md` 맨 위 "작은 소품 배정 순서"대로 `planRoom` 의 작은 단어 자리 고르기를 바꾼다(선반, 선반, 원탁, 선반, 바닥, 선반, 원탁, 바닥, 선반, 바닥). 큰 모델·벽·동물 짝은 그대로.
5. **낙하**: 새 칸 5개는 모두 `pop`(슬롯 `drop` 에 이미 있음). `drop_by_height` 줄은 필요 없다(작은 소품 칸이라).
6. **썸네일**: `thumbs/` 를 `app/src/assets/prop-thumbs/` 에 넣으면 `import.meta.glob` 이 자동으로 쓴다(파일이 없는 것만 임시 카드).
7. (선택) 방 위에서 보는 확인: `images/` 의 3장과 같은 모양이어야 한다(작은 소품 8개 → 선반 4·원탁 2·바닥 2).

## 4. 소품 썸네일 131개
- 대상: `interest_words_v3_8.json` 에서 **단어가 2개 이상인 소분류의 모델 131개**(`step4-5` 문서의 목록과 같음, 노드 이름 131개 일치). 큰 모델·벽 모델·동물 집 4개(`hamster_cage` `rabbit_hutch` `ant_farm_case` `lizard_tank`)도 포함.
- 규격(기획 확정, `room-interest-v3-8-step4-5.md` "결정 반영" 3번): **192×192 투명 WebP**, 파일당 12KB 이하, 모델 가장 긴 변이 캔버스의 **88%**(가운데 정렬), **방 카메라 쪽 각도**(정면에서 위로 10°, 직교 투영), **AgX 톤 · sRGB**(색 보정 없음), 파일 이름 = 노드 이름 정확히. 131개 전부 192×192, 최대 11.0KB, 합계 465KB(품질 90 그대로).
- 바닥·그림자판 없이 모델만(투명). 같은 조명·같은 노출로 모두 뽑아 대분류끼리 밝기가 같다.
- 정면 10° 각도라 납작한 소품(체중계, 신문, 직소퍼즐 등)은 얇게 보인다. 높이가 아니라 가장 긴 변을 88%로 맞췄기 때문이다.
