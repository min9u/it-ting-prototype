## 2. 개발팀이 할 일

1. **관심사 선택 화면**: `interest_words_v3_8.json`의 대분류 12·소분류 90(`tag`)으로 목록을 만들고, **최대 10개** 선택 (`max_pick`).
2. **모델 불러오기**: 대분류별 glb(`glb_compressed` 권장)를 읽고, 단어의 `node` 이름으로 노드를 복제해서 씀. `pet`이 있으면 동물 노드도 같이.
3. **배치**: `PLACEMENT_v3_8.md` 2·3번 규칙.
   - 소분류를 고르면 **첫 단어 모델** → 자리가 없으면 같은 소분류의 다음 단어
   - `작은` → 빈 선반 `prop_slot_01~12`
   - `큰` → 바닥 공용 자리 20칸 중 **회전 없이** 들어가는(`max_m` 안) 빈칸 중 바닥 면적이 가장 작은 칸
   - `벽` → 벽 공용 자리 04·18·20·24 중 같은 방식
   - 동물 짝 → `pet_slot_01~05` + `prop_slot_15~19` 빈 쌍 (동물·용품 위치 관계는 v3.4와 같음)
4. **기본 가구·두더지 자리 (v3.8 변경)**: `room_base_v3`로 바꾸고, **두더지 기본 자리를 (0, 0) → 원탁 앞 (0, −0.85) Blender = three.js (0, 0, 0.85)**로 옮김 (원탁이 가운데로 와서). 앉는 위치 `sit_point_cushion_01`(하늘)·`_02`(노랑)는 방석 자식 그대로, 둘 다 **카메라 쪽(−Y, 회전 0°)**을 보고 앉음. 걸어오는 시작점 = 방석 앞 0.7m: 노랑 (−0.68, −0.65), 하늘 (+0.68, −0.65) (Blender). 빈백 앉기(`sit_point_chair_01`)는 빈백을 안 쓰므로 없음
5. **낙하 연출**: 바닥 공용 자리는 모델 키(`big_model_sizes.json`의 `h`)로 `drop_by_height`에서 줄을 골라 `mode`/`H`/`S`/`dust`를 씀. 곡선·시간은 `furniture_drop_spec_v3_7.md` 그대로. 선반·벽은 `pop`.

## 3. 확인한 것

- glb 24개: 루트 이름이 `interest_words_v3_8.json`과 빠짐·남음 없이 일치, 루트 위치·회전·크기 기본값, 그림자판 없음, 압축본은 `KHR_draco_mesh_compression` + `EXT_texture_webp`
- 소분류 10개 선택 모든 조합 → 놓지 못하는 경우 0 (`PLACEMENT_v3_8.md` 4번)
- 바닥 20칸 + 벽 3칸 동시 배치 → 모델끼리 겹침 없음. 피아노 자리(01) 벽 묻힘은 회전으로 해결
- 낙하: 자리별·키 단계별 상자로 돔 5cm·걸이 소품/선반 3cm 조건 확인
- 원탁·방석(앉은 두더지 포함)·두더지 기본 자리·걸어오는 시작점이 모든 바닥 자리(공용·바닥 소품·반려동물·우체통)와 **10cm 이상** 떨어짐. 원탁↔방석 간격 4cm
- 두더지 몸으로 걷기·앉기·일어나기 전 프레임 거리 검사는 **아직 안 함** (v3.3 방식)

## 4. 아직 안 한 것 (알고 있는 것)

- **대분류별 전용 액세서리**(`interest_catalog.json`의 `accessories`: 헤드폰, 베레모 등)는 옛 대분류 기준 그대로. 새 대분류 12개에 다시 연결하지 않음
- 낙하 값은 **상자 기준이라 보수적** (큰 키 모델은 벽 쪽 자리에서 `pop`이 많음)
- 같은 소분류에서 어떤 단어를 먼저 놓을지 사용자가 고르는 UI는 없음 (지금은 첫 단어 우선)
- 침대·협탁을 뺀 왼쪽 빈자리(옛 침대 자리)는 아직 비어 있음. 공용 자리를 더 만들 수 있음
- 쓰지 않게 된 기존 모델 13개(도마, 팝콘, 빈백, 화이트보드 등)는 이 묶음에 넣지 않음 (원본 blend에는 남아 있음)
